# Environment Variables

Consolidated reference for all environment controls. The primary config file on macOS and Linux is `/etc/edgecoder/edgecoder.env`. See [`scripts/macos/payload/etc/edgecoder/edgecoder.env.example`](https://github.com/codyrs82/Edgecoder/blob/main/scripts/macos/payload/etc/edgecoder/edgecoder.env.example) for a fully-annotated template.

## Runtime mode

`NODE_ENV` (default `development`): `production` turns on the production-only checks listed under [Startup validation](#startup-validation-15).

| Variable | Values | Description |
|---|---|---|
| `EDGE_RUNTIME_MODE` | `worker` \| `coordinator` \| `ide-provider` \| `control-plane` \| `inference` \| `all-in-one` | Selects which service the daemon runs as. Required. |
| `HOST` | `127.0.0.1` | Listen address for all HTTP services; set `0.0.0.0` in containers/Fly or for LAN multi-machine setups. |

| `COORDINATOR_TRUST_PROXY` | `10.0.0.5` | Coordinator: comma-separated addresses of reverse proxies in front of it. ## Economy, payouts and receipts (coordinator)

| Variable | Default | Description |
|---|---|---|
| `RATE_ORACLE_ENABLED` | `true` | Enable the BTC/USD rate oracle (median of sources, daily clamp). Set `false` to freeze class reference pricing. |
| `RATE_RECALIBRATION_MS` | `86400000` | How often the rate oracle recalibrates its per-class reference rates (ms; min 60000). |
| `MARKET_DEFAULT_BID_PREMIUM_BPS` | `1000` | Default order-book bid premium over the oracle reference, in basis points. |
| `NETWORK_FEE_BPS` | `500` | Network fee skimmed into the fee pool on each settled trade, in basis points. |
| `HOST_HEARTBEAT_MS` | `60000` | Interval at which a host reports its uptime/services heartbeat (ms; min 1000). |
| `INFRA_HOST_REPORT_URLS` | _(unset)_ | Comma-separated coordinator URLs whose fee pool this host also reports to; each heartbeat is signed with `COORDINATOR_PRIVATE_KEY_PEM` and must come from a peer the receiver's mesh admitted. |
| `INFRA_HOST_LIGHTNING_NODE_ID` | _(unset)_ | This host's Lightning node id (`lncli getinfo` → `identity_pubkey`); a remote coordinator attests the `lightning` service by a BOLT 8 handshake against it on port 9735. |
| `INFRA_HOST_ELECTRS_ENDPOINT` | `electrs:50001` | Where this coordinator checks its own electrs (Electrum `server.version`) before counting the `electrs` service. |
| `HOST_ATTEST_ALLOW_PRIVATE` | _(unset)_ | `1` lets service probes of remote hosts target private/loopback addresses (local test networks only). |
| `FEE_POOL_DISTRIBUTION_MS` | `86400000` | Interval for distributing the network fee pool to hosts by uptime × services (ms; min 60000). |
| `PAYOUT_AUTO_INTERVAL_MS` | `21600000` | Interval for the LNURL auto-payout sweep (ms; min 60000). |
| `RECEIPT_EPOCH_MS` | `3600000` | Length of a signed-work-receipt Merkle epoch before it is sealed and anchored (ms). |
| `RECEIPT_REPLICATION_MS` | `60000` | How often sealed receipt epochs are replicated to peers (ms). |
| `PAYOUT_MAX_SINGLE_SATS` | mainnet `100000`, else `0` | Largest single payout incl. its routing-fee cap, in sats; `0` = no cap. Over-limit payouts are rejected and logged as `payout_limit_exceeded`. |
| `PAYOUT_MAX_ACCOUNT_DAILY_SATS` | mainnet `500000`, else `0` | Paid + pending payouts per account over a rolling 24 h (pending at their fee cap), in sats; `0` = no cap. |
| `PAYOUT_MAX_GLOBAL_DAILY_SATS` | mainnet `2000000`, else `0` | Paid + pending payouts from this coordinator's database over a rolling 24 h, in sats; `0` = no cap. |
| `PAYOUTS_PAUSED` | _(unset)_ | `1` halts withdrawals, auto payouts and fee-pool distribution on this instance; cannot be lifted over the API. Purchases keep working. The shared flag is toggled with `POST /admin/payouts/pause`. |
| `PAYOUT_RECONCILE_MS` | `600000` | How often the ledger is reconciled against the Lightning node's balances and payments (ms; min 60000; `0` = timer off). A mismatch pauses payouts. |
| `PAYOUT_RECONCILE_TOLERANCE_SATS` | `1000` | Slack per reconciliation check, in sats. |
| `PAYOUT_RECONCILE_LOOKBACK_MS` | `86400000` | How far back the first reconciliation after a start reads node payments (ms). |
| `PAYOUT_ALERT_WEBHOOK_URL` | _(unset)_ | POSTed a JSON summary (counts, amounts, payment hashes; no secrets) when reconciliation alerts or trips. |
| `MOCK_LIGHTNING_BALANCE_SATS` | `0` | Dev only: starting balance of the mock Lightning wallet. |

## Mesh auth and security

| Variable | Description |
|---|---|
| `MESH_AUTH_TOKEN` | Shared mesh auth secret. Auto-provisioned by coordinator on successful registration if left blank. |
| `COORDINATOR_MESH_TOKEN` | Alias for `MESH_AUTH_TOKEN`. Keep aligned if both are set. |
| `MESH_PEER_ALLOWLIST` | #52: comma-separated `peerId:fingerprint@https://peer-url` entries for the peer coordinators this coordinator trusts. `@url` pins the peer's endpoint, and gossip never changes it. **In production every entry must have `@url`, or the coordinator refuses to start.** `fingerprint` is the SHA-256 (hex) of the peer's SPKI public key. With the mesh token, a peer must also be on this list and sign its registration with that key. Results it forwards must be signed too. **Required in production**: without it, token-only peer registration and forwarded results are rejected. In dev an empty list keeps the old token-only behaviour. |
| `COORDINATOR_PRIVATE_KEY_PEM` | Ed25519 private key (PKCS#8 PEM) for this coordinator's mesh identity. Set it on every coordinator that peers, since a generated key changes on each restart and would drop off its peers' allowlists. Fingerprint for `MESH_PEER_ALLOWLIST`: `node -e 'const c=require("crypto");const k=c.createPublicKey(process.env.COORDINATOR_PRIVATE_KEY_PEM);console.log(c.createHash("sha256").update(k.export({type:"spki",format:"der"})).digest("hex"))'` |
| `INFERENCE_AUTH_TOKEN` | Auth token for the inference service API. |
| `ADMIN_API_TOKEN` | Admin token for control-plane operator APIs. |
| `PORTAL_SERVICE_TOKEN` | Internal service token for portal ↔ coordinator/control-plane calls. |
| `ENABLE_DEBUG_ROUTES` | Set `1` to register coordinator `/debug/*` routes (dev/e2e only; never registered in production). |
| `PORTAL_ALLOW_OPEN_INTERNAL` | Set `1` (non-production only) to leave portal `/internal/*` open when `PORTAL_SERVICE_TOKEN` is unset; otherwise those routes return 503. |
| `REQUIRE_SIGNED_AGENT_REQUESTS` | Default `true`, always `true` in production. Agent `/heartbeat`, `/pull` and `/result` must carry signed request headers (`x-agent-id`, `x-timestamp-ms`, `x-nonce`, `x-body-sha256`, `x-signature`). The TS worker and the iOS app (#64, `RequestSigner.swift`, Keychain-held key registered via `publicKeyPem` in `/register`) both sign this way; shared vectors live in `tests/security/fixtures/request-signing-vectors.json`. Set `false` only for local dev with legacy unsigned agents. A signed request's `x-body-sha256` must be the sha256 of the exact body bytes received. `/benchmark/response` is signed-only whatever this is set to. Nonces are kept in Postgres (`request_nonces`) when `DATABASE_URL` is set, so replays are refused across restarts and seeds. |
| `MESH_WS_REQUIRE_SIGNED` | Default `false`. `true` refuses `/mesh/ws` connections without a signed bind (`x-mesh-ws-ts` + `x-mesh-ws-signature` from the peer's registered key). Unsigned binds (older agents) never replace an authenticated connection, and every message must come from the bound peer either way. |
| `EDGECODER_TRUST_MODE` | Agent: `tofu` (default), `strict` or `open`. How the agent trusts coordinator keys (docs/receipts-and-trust.md); switch-over to `strict` in docs/going-to-mainnet.md. `strict` with no keys listed refuses to start. |
| `TRUSTED_COORDINATOR_KEYS` | Agent: comma-separated `peerId:fingerprint` (sha256 of the SPKI DER; `GET /identity` → `trustEntry`). Older PEM-text fingerprints are still accepted. |
| `EDGECODER_TRUST_FILE` | Agent: trust file path (default `<config dir>/trusted-coordinators`); one `peerId:fingerprint` per line; tofu appends first-seen keys. |

## Result verification (#50, #106)

| Variable | Default | Description |
|---|---|---|
| `RESULT_VERIFICATION_RATE` | `0` | Base fraction of subtasks re-executed for verification. `0` = verification off (the default). |
| `RESULT_VERIFICATION_ABANDON_PENALTY` | `0.25` | Reputation lost for claiming a verification replica and never reporting it. |
| `RESULT_VERIFICATION_REPLICA_CLAIM_TIMEOUT_MS` | `300000` | A claimed replica with no report after this long is reassigned to an agent other than the abandoner(s). |
| `RESULT_VERIFICATION_MAX_REASSIGNMENTS` | `1` | How many times one sampled subtask's stalled replica is reassigned (0–10). After that the subtask waits for the overall timeout. |
| `RESULT_VERIFICATION_INITIAL_REPUTATION` | `0.5` | Reputation (0–1) of an agent id the coordinator has never seen. Below 1 so a caught agent can't regain full trust by re-registering; lower reputation means its results are re-executed more often. |
| `RESULT_VERIFICATION_MAX_EXECUTIONS` | `3` | Max executions of a sampled subtask (original + replicas), 2–3. Values above 3 are capped. At most this minus one replicas run per sampled subtask; whether winning replicas are paid is set by `RESULT_VERIFICATION_MINT_REPLICA_REWARDS`. |
| `RESULT_VERIFICATION_MINT_REPLICA_REWARDS` | `false` | Pay winning verification replicas from newly minted compute credits (`true`/`1`/`yes` to enable). Off by default: only the original execution is paid, so verification doesn't add to the credit supply. **Enabling minting requires Cody's approval.** The coordinator logs a startup warning whenever `RESULT_VERIFICATION_RATE` is above 0, saying whether replicas are paid. |

## Startup validation (#15)

Each service reads its environment once at startup through a zod schema. An invalid value (for example `abc` for an interval, `maybe` for a flag, or a URL without `http(s)://`) stops the service, and the error lists every problem at once. Empty values count as unset. A `docs coverage` test (`tests/common/env-docs.test.ts`) fails if a schema key is missing from this page.

| Service | Schema | Production-only rules |
|---|---|---|
| inference | `src/inference/config.ts` | `INFERENCE_AUTH_TOKEN` at least 32 characters |
| portal | `src/portal/config.ts` | `PORTAL_SERVICE_TOKEN`, `WALLET_SECRET_PEPPER`, `RESEND_API_KEY`, `DOCS_SITE_URL` required; `CONTROL_PLANE_URL` or `COORDINATOR_DISCOVERY_URLS`; `CONTROL_PLANE_ADMIN_TOKEN` when `CONTROL_PLANE_URL` is set; https for `PORTAL_PUBLIC_URL`, `DOCS_SITE_URL` and passkey origins |
| coordinator | `src/swarm/coordinator-config.ts` | unchanged (`requireProdEnv`) |
| control-plane | `src/control-plane/config.ts` | `ADMIN_API_TOKEN` required in every environment |

### Alerting on 5xx without Sentry

Every service exports `edgecoder_http_requests_total{service,method,route,status}`. Example Prometheus rules:

```yaml
groups:
  - name: edgecoder-http
    rules:
      - alert: EdgeCoderHigh5xxRate
        # more than 5% of requests failing with 5xx for 10 minutes, per service
        expr: |
          sum by (service) (rate(edgecoder_http_requests_total{status=~"5.."}[5m]))
            / sum by (service) (rate(edgecoder_http_requests_total[5m])) > 0.05
        for: 10m
        labels: { severity: page }
      - alert: EdgeCoder5xxOnRoute
        # any single route returning 5xx steadily (catches a broken endpoint on a busy service)
        expr: sum by (service, route) (rate(edgecoder_http_requests_total{status=~"5.."}[5m])) > 0.1
        for: 15m
        labels: { severity: ticket }
      - alert: EdgeCoderMetricsMissing
        # the scrape itself failing usually means the service is down or METRICS_TOKEN is wrong
        expr: up{job=~"edgecoder-.*"} == 0
        for: 5m
        labels: { severity: page }
```

Scrape `/metrics` (inference: `/metrics/prometheus`) with `authorization: Bearer $METRICS_TOKEN`. `route` is the route pattern, so these rules stay low-cardinality.

## Operational guidance

**Production fail-fast (#5).** With `NODE_ENV=production`, services refuse to boot when required secrets are empty (an empty token no longer means "auth off"):
- coordinator: `MESH_AUTH_TOKEN`, `PORTAL_SERVICE_URL`, `PORTAL_SERVICE_TOKEN`, `ADMIN_API_TOKEN`, `PAYMENT_WEBHOOK_SECRET`, and `LIGHTNING_PROVIDER` unless `ECONOMY_PAYMENTS_ENABLED=false`
- portal: `PORTAL_SERVICE_TOKEN`, `WALLET_SECRET_PEPPER`, `RESEND_API_KEY` (plus the existing passkey/URL checks)
- inference: `INFERENCE_AUTH_TOKEN`
- control-plane: `ADMIN_API_TOKEN`

Run a `fly secrets list` checklist against this list before any deploy.

- Keep secrets in production secret stores (Fly Secrets, AWS SSM, etc.) rather than static env files.
- On macOS, the env file is `/etc/edgecoder/edgecoder.env` (chmod 600, owned by root).
- On Linux, same path — the systemd `EnvironmentFile=-/etc/edgecoder/edgecoder.env` directive loads it.
- Review and rotate `MESH_AUTH_TOKEN` periodically.
